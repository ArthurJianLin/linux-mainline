二、高优先级候选（P1–P3）

P1 · mm/page_alloc.c — 无效 EXPORT_SYMBOL 优先提交

位置：mm/page_alloc.c:5464

struct page *__alloc_frozen_pages_noprof(gfp_t gfp, unsigned int order, ...)
{
	...
	return page;
}
EXPORT_SYMBOL(__alloc_frozen_pages_noprof);   /* <-- 待删除 */

为什么是无效导出（证据链完整，不可辩驳）：

  • 该函数声明仅存在于 mm/page_alloc.h（mm 私有头文件），任何公共头文件均无声明——树外/树内模块无法规范引用；
  • 全树使用者仅 4 处，全部在 mm/ 内且全部为内建目标：mm/mempolicy.c（CONFIG_NUMA 为 bool）、mm/slub.c（CONFIG_SLUB 为 def_bool y）、mm/page_alloc.c 自身及宏包装；
  • mm/ 下全部 tristate 目标（ZSMALLOC、HWPOISON_INJECT、DMAPOOL_TEST、KUnit）均不使用该 API；全树（含 rust/、.S、.rst）无任何引用；
  • EXPORT_SYMBOL 的唯一目的是供模块使用，此处永不生效。引入于 49249a2a5eeb（Willy，2024-11），系 __alloc_pages() 重构遗留。

建议 commit message：

Subject: mm/page_alloc: drop unneeded EXPORT_SYMBOL for __alloc_frozen_pages_noprof

__alloc_frozen_pages_noprof() is only declared in mm/page_alloc.h, which
is private to the mm/ built-in code.  All in-tree users
(mm/page_alloc.c, mm/mempolicy.c and mm/slub.c) are built-in, and no
module can reference this symbol anyway.  Drop the export.

Fixes: 49249a2a5eeb ("mm: introduce __alloc_frozen_pages()")
Signed-off-by: <施老师> <邮箱>

P2 · include/linux/pgtable.h — 文档参数名错误 优先提交

位置：include/linux/pgtable.h:657-677

/**
 * clear_young_dirty_ptes - Mark PTEs that map consecutive pages of the
 *		same folio as old/clean.
 * @mm: Address space the pages are mapped into.      /* <-- 应为 @vma */
 ...
 */
static inline void clear_young_dirty_ptes(struct vm_area_struct *vma,
					  unsigned long addr, pte_t *ptep,
					  unsigned int nr, cydp_t flags)

签名第一个参数是 struct vm_area_struct *vma，kernel-doc 却写成 @mm。kernel-doc 工具双重报警：Excess function parameter 'mm' + parameter 'vma' not described。追溯 1b68112c4039（2024-04）——注释从诞生起就写错，两年无人修正。arm64 实现（arch/arm64/include/asm/pgtable.h:1948）使用 vma 参数，与 generic 一致。

修法：一行替换 @mm: Address space the pages are mapped into. → @vma: the VMA that the folio is mapped into.。建议 Subject：mm: pgtable: fix wrong parameter name in clear_young_dirty_ptes() docs。该文件归 arch/mm 共同维护，get_maintainer 会拉出较长 Cc 列表，属正常。

P3 · mm/mremap.c — 注释描述已消亡的行为 优先提交

位置：mm/mremap.c:1022-1026

/*
 * Update mm exec_vm, stack_vm, data_vm, and locked_vm fields as needed to
 * account for 'bytes' memory used, and if locked, indicate this in the VRM so
 * we can handle this correctly later.       /* <-- 描述的行为已不存在 */
 */
static void vrm_stat_account(struct vma_remap_struct *vrm,
			     unsigned long bytes)
{
	...
	vm_stat_account(mm, vma->vm_flags, pages);
	if (vma_test(vma, VMA_LOCKED_BIT))

git 历史直接证实：初始版本（d5c8aec0542e）函数体内确有 vrm->mlocked = true;，对应注释 "indicate this in the VRM"；2cf442d74216（2025-07，mm/mremap: clean up mlock populate behaviour）把该判断移入 check_prep_vma() 并重命名为 populate_expand，删除了此处赋值，但注释原样保留，误导读者以为此函数有副作用。

修法：删除 "and if locked, indicate this in the VRM so we can handle this correctly later" 一句。建议 Subject：mm/mremap: remove stale comment about VRM mlocked tracking in vrm_stat_account()。

三、W=12 编译警告挖出的死代码（P4）

位置：mm/shmem.c:5325-5331（#if defined(CONFIG_SYSFS) && defined(CONFIG_TMPFS) 块内）

W=12 编译报 4 个 unused macro（__INIT_KOBJ_ATTR、TMPFS_ATTR_W、TMPFS_ATTR_RW、TMPFS_ATTR_RO）。逐一定性后：TMPFS_ATTR_RO 被 casefold 属性使用（在 IS_ENABLED(CONFIG_UNICODE) 条件内，arm64 defconfig 未启用 UNICODE 才报警），__INIT_KOBJ_ATTR 是其依赖，均不能动；但 TMPFS_ATTR_W 与 TMPFS_ATTR_RW 经全仓库 grep（.c/.h/.S/.rs）确认零引用，是真正的死代码，引入自 18d2f10f6284（tmpfs: Fix type for sysfs' casefold attribute）——当时只迁移了 RO 变体，顺手写全了三件套。

修法：删除 TMPFS_ATTR_W 与 TMPFS_ATTR_RW 两个宏定义（共 8 行）。建议 Subject：shmem: remove unused TMPFS_ATTR_W/RW macros。注意：不要顺手"修复"另两个宏的警告（如挪 ifdef），保持 patch 最小化。

W=12 其余警告定性说明：46 条警告中约 20 条 -Wshadow（如 vmstat.c、rmap.c、truncate.c 的局部变量遮蔽）属社区已知噪音，单独成 patch 不受 maintainer 待见；memblock.c:33 INIT_PHYSMEM_REGIONS 在 CONFIG_HAVE_MEMBLOCK_PHYS_MAP（x86）下有使用，属配置差异噪音；secretmem.c:31 pr_fmt 未用价值过低，均不建议提交。

四、kernel-doc 系列候选（P5–P8）

四个问题均为 kernel-doc 工具机器确认的格式缺陷，建议打成一个 cover letter 系列（或各自独立小 patch），示例 cover subject：[PATCH 0/4] mm: fix kernel-doc issues：

  • P5 · mm/page_reporting.h:25：page_reporting_notify_free(unsigned int order) 函数体直接依赖 order（if (order < page_reporting_order)），kernel-doc 却无 @order: 行。补一行 @order: order of the page being freed。
  • P6 · mm/percpu.c:766：pcpu_block_refresh_hint 注释缺 short description（直接以 * pcpu_block_refresh_hint\n * @chunk: 开始）。改为 pcpu_block_refresh_hint - update hints after a block change。
  • P7 · mm/memory_hotplug.c:2229：try_offline_node 同样缺 short description。改为 try_offline_node - offline a node if all its sections/CPU are removed。
  • P8 · include/linux/swapops.h:45：migration swap entry 位布局图表注释误以 /** 开头，导致 kernel-doc 解析器报警（会被误认为可解析注释）。改为 /* 即可。

六、已排除的假阳性（避免踩坑）

候选 → 证伪过程（这些看起来像 bug，但实际不是）
候选排除理由
shake_folio、hwpoison_filter_register/unregister 的 EXPORT_SYMBOL_GPL（声明在 mm/internal.h 却导出，树内无外部使用者）CONFIG_HWPOISON_INJECT 是 tristate；当 =m 而 MEMORY_FAILURE=y 时，hwpoison-inject 模块调用这些符号必须有导出
hugetlb_wp() spin_lock(3)/unlock(2) 不平衡函数末尾注释 "Caller expects lock to be held"，错误路径带锁返回是该 API 契约
filemap.c:3091 等 3 处 max_t(ssize_t, pipe->max_usage - used, 0) 疑似 unsigned 下溢防护失效实际正确：unsigned wrap 值经 (ssize_t) cast 后按补码解释为负数，max(负数, 0)=0 恰好完成 clamp
memfd_luo.c retrieve 错误路径引用计数kho_restore_folio() 返回 refcount=1 的 folio，三种失败路径的 unlock+put/unlink 组合全部对称
migrate_device_coherent_folio() folio_lock 后无 unlock锁释放委托给 __migrate_device_finalize()（其中 folio_unlock(src)），跨函数对称
MREMAP_DONTUNMAP 的 locked_vm 会计（397432cab17b 刚修过）当前实现：源 VMA 清 LOCKED 但遗留旧账恰好代表新 VMA 的锁定，munmap 新 VMA 时回收，数学守恒
do_brk_flags 记账不查 vma_supports_mlockbrk 恒为匿名 VMA，该检查恒真，合理省略（对比 __mmap_complete 需处理文件映射故有检查）

七、提交路径与时机建议

  • 收件人：mm 补丁发 linux-mm@vger.kernel.org，Cc akpm@linux-foundation.org；用 ./scripts/get_maintainer.pl --no-rolestats your.patch 生成完整 Cc 列表；
  • 格式自检：./scripts/checkpatch.pl --strict your.patch 必须零 ERROR/WARNING（本轮验证近期 mm 提交全过，maintainer 对格式零容忍）；
  • 时机：当前 v7.3-rc4，7.4 合并窗口即将打开——cleanup/doc 类 patch 正是排队好时机（akpm 树全年收，但窗口前后合入最快）；
  • 建议提交顺序：P1（证据链最硬）→ P2（一行修复）→ P3 → P4 → P5-P8 打包一个系列；每个 patch 保持单一目的、最小 diff；
  • Sendmail/客户端：推荐 git send-email（纯文本、无 HTML、无折叠），需配置 SMTP。

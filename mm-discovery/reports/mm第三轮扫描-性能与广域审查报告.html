三、性能观察项清单（跟踪但不建议立即提交）

以下四个观察项机制都真实存在，但均不建议本轮提交——三条卡在"作者活跃迭代的新框架"（撞车风险），一条卡在"收益太小"（审阅人要求 benchmark 数据时无法自证）。它们的价值在于持续跟踪上游进展，在框架沉淀后跟进：

O-1 · memcontrol.c:3661 — slabobj_ext 记账批量化 作者自留 TODO

__memcg_slab_alloc_hook() 的批量分配路径中，每个对象独立走一遍 stock 消费/回填序列。作者注释明写：TODO: we could batch this until slab_pgdat(slab) changes between iterations, with a more complicated undo。slabobj_ext 是 7.x 新框架、作者活跃迭代中——撞车风险最高的观察项，建议只跟踪不抢跑。

O-2 · swap_state.c — 批 swapin 的 cluster lock 合并 新框架活跃期

__swap_cache_alloc() 中每个 folio 独立完成 cluster lock → add → unlock + memcg charge + 统计 + LRU add 序列（449-493 行）。同 cluster 批 swapin 场景可一次锁内完成多个 add。但该区域 7.2/7.3 刚被 swap_io_ctx 系列重构，作者正在快速跟进版本（如 Kairui 的 mTHP swap-in 系列），同样建议跟踪。

O-3 · memfd_luo.c:188 — KHO preserve 的 folio 清零优化 作者标注

KHO（Kexec HandOver，7.3 新特性）的 memfd_luo_preserve_folios() 中，非 uptodate 的 fallocate 空洞页被逐个 folio_zero_range()。作者注释明写 NOTE: For someone looking to improve preserve performance, this is a good place to look——是一份公开的性能改进邀请，但 liveupdate 属一次性操作，收益场景限于高频热迁移。

O-4 · mempolicy.c — weighted interleave 总权重缓存 本轮证伪

见第五节证伪记录：曾作为候选深挖，最终因 nodemask 依赖与典型节点数过小而放弃。

四、正确性补扫：KHO memfd_luo 资源对称性

第一轮只人工核过 memfd_luo.c 的 retrieve 路径引用计数（当时证伪），本轮补扫了 preserve/unpreserve 全链路：

  • preserve_folios 错误回滚链：err_unpreserve → err_unpin → err_free_folios 三级标签的回滚对象精确对应（kho_unpreserve_folio() 只回滚已 preserve 的 folios 0..i-1；kho_preserve_vmalloc() 失败时 i==nr_folios 走全量回滚，数学正确）；
  • unpreserve_folios 对称性：逐 pfolio kho_unpreserve_folio + unpin_folio，与 preserve 的 pin + preserve 逐项配对；pfn==0 跳过分支对应 preserve 时的零尺寸文件捷径；
  • pin 引用计数：memfd_pin_folios() 返回 nr_pinned 与 unpin_folios(folios, nr_folios) 精确对称，vfree(folios_ser) 对应 vcalloc。

结论：KHO memfd_luo 的资源对称性干净，7.3 新文件的错误路径没有发现可提交缺陷。

六、第一轮候选 7.3 存活复核 + mm-unstable 撞车复查 复核后归档

第一轮 8 个候选基于 v7.3-rc4，本轮在 7.3 正式版（c03c1a14）逐条复核，并对两个最高优先候选做了 mm-unstable（akpm 补丁队列，比 torvalds 更新）的撞车复查：

  • P1（mm/page_alloc.c:5464 无效 EXPORT_SYMBOL(__alloc_frozen_pages_noprof)）：7.3 原样存在 ✓；mm-unstable 上 cgit 提交搜索 "frozen_pages" 共 86 条提交[1]，无任何删除该导出的清理提交（最接近的 export free_frozen_pages() instead of free_unref_page() 是另一处导出调整）——未撞车；
  • P2（include/linux/pgtable.h:660 clear_young_dirty_ptes() 文档参数名 @mm 应为 @vma）：7.3 原样存在 ✓；mm-unstable 的 pgtable.h 文件实拉对照（20KB，git.kernel.org plain 通道）@mm 原样保留——未撞车[2]；
  • P3（mm/mremap.c vrm_stat_account() 过时注释）、P4（mm/shmem.c:5328/5332 死宏）、P5-P8（kernel-doc 四件套）：7.3 正式版全部原样存活 ✓（与 rc4 同源，无需重复判重结论）。

归档决定（质量优先原则）：第一轮 8 个候选全部属于 cleanup/doc 类小修小改——无功能影响、无运行时收益，逐个提交只会累积数量而非贡献质量。虽然事实层面它们全部存活且未撞车，按本轮决策全部归档为低价值，不再作为行动项。当前阶段只投入两类 patch：真实逻辑修复（如 mremap Committed_AS 泄漏）与带 benchmark 数据支撑的实质性能优化。
